## 云端模型过滤内容时的翻译失败处理

- 2026-09-23 实测：火山方舟 `deepseek-v4-flash-ga-260731` 翻译一段日文记者提问时，HTTP 200 的 Chat Completions 响应包含 `finish_reason: content_filter`，`message.content` 是“无法回答”一类拒答文字；应用目前会把它显示为译文。英文对照文本可正常翻译。
- 同一段原文改用更简短的翻译提示词仍被过滤；拆句后定位到含“米中首脳会談”的短语单独请求也被过滤。当前证据表明这是模型服务的内容过滤，不是内置提示词造成的。
- 待设计跨模型、跨服务商的失败识别与展示：分别处理 `finish_reason: content_filter`、结构化 `refusal`、HTTP 错误代码，以及只在普通文本里返回拒答的情况。不能仅靠匹配某句拒答文案；需用多个提供商的实际响应验证，并避免把过滤或不完整输出展示为成功译文。
- 内容过滤由模型服务决定；应用层的错误提示无法保证原文在该模型上可译。后续可评估让用户选择其他模型重试。
- 验证所用 API Key 未写入仓库。
